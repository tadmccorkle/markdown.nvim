INTRODUCTION                                                   *markdown.nvim*

|markdown.nvim| is a plugin that provides tools for working with markdown
files in Neovim, including inline-style keybindings over vim motions and
convenience features like table of contents insertion and auto-numbering of
ordered lists.

================================================================================
USAGE                                                         *markdown.usage*

|markdown.nvim| is broken up into different feature categories:

* Inline Surround (|markdown.inline|)
* Table of Contents (|markdown.toc|)
* List Editing (|markdown.lists|)
* Table Editing (|markdown.tables|)
* Links (|markdown.links|)
* Navigation (|markdown.navigation|)

INLINE SURROUND                                              *markdown.inline*

|markdown.nvim| provides keymaps to toggle, delete, and change emphasis and
code spans, which will also be referred to in this section as "styles". The
supported styles and the default keys used to refer to them are:

* emphasis (typically rendered in italic)   "i"
* strong (typically rendered in bold)       "b"
* strikethrough                             "s"
* code span                                 "c"

Keymaps are set up after |markdown.nvim| is either configured with a call to
|markdown.setup()| or registered as an |nvim-treesitter| module (see
|markdown.configuration|). |<Plug>| mappings are created regardless of
configuration (see |markdown.plug_mappings|).

TOGGLE                                                *markdown.inline.toggle*

Inline styles can be toggled over vim motions in normal and visual mode.
Toggled styles are only applied to appropriate markdown elements (i.e., not
blank lines, list markers, etc.). For example, a motion that includes a list
marker and multiple blocks will only apply the style to inline content:

                       toggle strong over five lines ~
>
            paragraph block                    **paragraph block**
            - list item                        - **list item**
                                   ---->
            another paragraph                  **another pargraph
            over two lines                     over two lines**
<
In normal mode this is done with `gs{motion}{style}`, where `{style}` is
the key corresponding to the style to toggle (by default "i", "b", "s", or
"c"). Like other vim motions, a |[count]| can be specified before and after
the `gs`. Emphasis can also be toggled over the current line using
`gss{style}`. A |[count]| can be specified to toggle over multiple lines.

        Before                  Command             After ~
>
        ^some text              gs2es               ~~some text~~
        some t^ext              gsiwb               some **text**
        some *t^ext*            gsiwi               some text
        ***some^ text***        gssb                *some text*
<
`^` denotes cursor position

Styles can be toggled in visual mode based on a visual selection using
`gs{style}`.

        Before                  Command             After ~
>
        ^some text$             gss                 ~~some text~~
        some ^text$             gsb                 some **text**
        some *^text$*           gsi                 some text
        ***^some text$***       gsb                 *some text*
<
`^` and `$` denote selection start and end, respectively

Styles can also be toggled in visual block mode.

        Before                  Command             After ~
>
        - list ^item$ 1                             - list *item* 1
        - li2                                       - li2
                                gsi
        - list ^item$ 3                             - list *item* 3
        - list ^item$ 4                             - list *item* 4
<
`^` and `$` denote block selection start and end on each line, respectively

See |markdown.config.on_attach| for an example of how to configure
standard/typical inline style keybindings in visual mode like `<C-b>` for
strong/bold and `<C-i>` for for emphasis/italic.

DELETE                                                *markdown.inline.delete*

Inline styles around the cursor can be deleted in normal mode using
`ds{style}`, where `{style}` is the key corresponding to the style to
delete (by default "i", "b", "s", or "c"). Only the style directly surrounding
the cursor will be deleted.

        Before                  Command             After ~
>
        **some^ *text***        dsb                 some *text*
        **some *t^ext***        dsb                 some *text*
        **some **t^ext****      dsb                 **some text**
<
`^` denotes cursor position

CHANGE                                                *markdown.inline.change*

Inline styles around the cursor can be changed in normal mode using
`cs{from}{to}`, where `{from}` and `{to}` are the keys corresponding to the
current style (`{from}`) and the new style (`{to}`) (by default "i", "b", "s",
or "c"). Only the matching `{from}` style directly surrounding the cursor will
be changed.

        Before                  Command             After ~
>
        **some^ *text***        csbi                *some *text**
        **some *t^ext***        csbi                *some *text**
        **some **t^ext****      csbs                **some ~~text~~**
<
`^` denotes cursor position

TABLE OF CONTENTS                                               *markdown.toc*

A table of contents (TOC) is created from the top-level (i.e., not within a
container like lists or block quotes) headings of markdown buffers.

Heading destinations are made unique in document order with -1, -2, etc.
suffixes, skipping destinations already in use. For example, Heading, Heading,
Heading 1 produce #heading, #heading-1, #heading-1-1. All non-container
headings count, even those omitted from the TOC or excluded by its max level.
Link navigation uses the same destinations, including headings in other files.
These anchors are GitHub-like, not guaranteed to match GitHub or other
renderers.

                                                                *:MDInsertToc*
:MDInsertToc[/max_level][/markers...]
:MDInsertToc [max_level] [markers...]

        Adds a TOC for the current buffer by inserting (normal mode) or
        replacing selected lines (visual mode). The TOC is based on ATX and
        setext headings.

        Optional arguments can be separated by `/` or whitespace. When
        separated by `/`, markers will include any leading or trailing
        whitespace. Multiple markers can be specified (for example,
        `:MDInsertTOC - +` or `:MDInsertTOC/-/+`).

        Ordered lists are specified with `"."` and `")"` marker arguments.

        Arguments:
            * max_level     max heading level to include
                            Default: "6"

            * markers       markers to alternate through for each heading
                            level
                            Default: "-" (unless overridden by configuration)
                            See: |markdown.config.toc.markers|

                                                                      *:MDToc*
:MDToc [max_level] [size]

        Shows a TOC for the current buffer in the current window's location
        list. Any flagged headings (see |markdown.toc.omit|) will also be
        omitted in the location list.

        Forwards command modifiers to |:lopen|. For example, the location list
        can be made a full-height vertically split window with a width of 40
        by executing `:vertical topleft MDToc * 40`.

        Arguments:
            * max_level     max heading level to include (non-number arguments
                            are ignored, falling back to the default)
                            Default: "6"

            * size          desired size (width or height) of the loclist
                            Default: none, see |:lopen|

                                                                   *:MDTocAll*
:MDTocAll [max_level] [size]

        Like |:MDToc|, but includes headings flagged as omitted.

OMIT HEADINGS                                              *markdown.toc.omit*

Headings and entire sections can be omitted from the TOC by flagging them with
`<!-- toc omit heading -->` and `<!-- toc omit section -->`, respectively. The
flag can either be placed directly above (i.e., on the line immediately
preceding) or within the heading content. For example, the following headings
would be omitted:
>markdown
        # heading 1 <!-- toc omit heading -->

        <!-- toc omit heading -->
        ## heading 2

        ## heading <!-- toc omit heading --> 3

        Heading 4 <!-- toc omit heading -->
        ---------

        <!-- toc omit heading -->
        Heading 5
        ---------

        <!-- toc omit section -->
        # section heading omitted
        ## subsection heading also omitted
<

LIST EDITING                                                  *markdown.lists*

INSERT ITEMS                                      *markdown.lists.insert_item*

The list item insertion commands are intended to be invoked by custom keymaps.
(see |markdown.config.on_attach|). Both commands maintain the same
indentation and list marker as the item under the cursor. The commands do
nothing if the cursor is not within an existing list.

When inserting an item in an ordered list, numbering is reset automatically
for that list. To reset numbering for all ordered lists in a buffer see
|markdown.lists.reset_numbering|.

                                                            *:MDListItemBelow*
:MDListItemBelow        Inserts a new list item below the current cursor
                        position.

                                                            *:MDListItemAbove*
:MDListItemAbove        Inserts a new list item above the current cursor
                        position.

RESET NUMBERING                               *markdown.lists.reset_numbering*

                                                       *:MDResetListNumbering*
:MDResetListNumbering   Resets the numbering of all ordered lists in the
                        current buffer (normal mode) or under selected lines
                        (visual mode).

TOGGLE TASKS                                      *markdown.lists.toggle_task*

                                                               *:MDTaskToggle*
:MDTaskToggle           Toggles the task(s) on the current cursor line (normal
                        mode) or under selected lines (visual mode).

TABLE EDITING                                                *markdown.tables*

Format GFM pipe tables with these buffer-local commands:

:MDTableFormat                                           *:MDTableFormat*
    Format the table at the cursor, including when on its separator row.
:[range]MDTableFormat
    Format whole tables intersecting the range (including visual selections).
:MDTableFormatAll                                        *:MDTableFormatAll*
    Format every table in the document. Equivalent to :%MDTableFormat.
:MDTableEdit                                             *:MDTableEdit*
    Open the current table in a floating modal editor. Outside a table, stage a
    new one-column, header-only table; insert it only when saved. Blank lines
    are replaced; otherwise the table is inserted after the cursor line with
    blank-line separation.
:MDTableExport                                           *:MDTableExport*
    Copy the staged table into a regular scratch split. Useful after a source
    conflict; does not commit or discard the staged table.

Formatting adds outer pipes and consistent padding, using the separator row's
colons for left/right/center alignment. Unicode uses display widths; tabs expand
using the source buffer's 'tabstop'. Missing cells are filled and surplus cells
become extra columns. Inline Markdown and escaped pipes are preserved. Tables
inside lists and blockquotes retain their prefixes. Fenced code is not changed.
Cursor-based formatting does nothing away from a table.

Table editor keys (Normal mode): ~
    h/j/k/l, arrows     Move between cells, including the header; clamp at edges
    Tab, w, e          Next cell, wrapping
    Shift-Tab, b       Previous cell, wrapping
    Enter or i         Open a separate cell-editing float in Insert mode
    o / O              Insert a body row below / above
    ci / ca            Insert a column before / after
    dd / yy            Delete / yank row (header deletion is forbidden)
    dc / yc            Delete / yank column (last-column deletion is forbidden)
    dx / yx            Clear / yank cell
    .                  Repeat the last successful row/column/cell deletion
    P / p              Paste above/before or below/after; cells overwrite
    al/ac/ar/an        Column alignment: left/center/right/unspecified
    u / Ctrl-r         Undo / redo an operation
    g- / g+            Earlier / later history state, including undo branches
    Ctrl-g             Toggle cell navigation / content navigation
    ?                  Show keymaps in a dedicated help float
    s or Ctrl-y        Save the formatted table to the source buffer and close
    q                  Discard all staged edits and close
    Esc                Return to cell navigation; otherwise discard and close

Cell navigation is the default. Content navigation removes the cell-motion
bindings, allowing native Vim motions, scrolling, and Visual selections. Both
modes keep the preview nonmodifiable, with supported table actions available.
The active cell follows native cursor moves and mouse clicks, including near
borders. The separator selects the header. Press Ctrl-g or Esc to return from
content navigation. The preview contains only table text, not a keymap guide.

Use V and native Visual-line motions to select multiple rows. Then d/x deletes
and y yanks; P/p pastes the whole group in order as one operation. The separator
is ignored. Deletion skips the protected header; yanking may include it. A multi-row
deletion is repeated with . using the same row count at the current cell. Protected
or no-op deletions do not replace the last successful deletion. Characterwise
Visual yanking remains native in content-navigation mode.

The separator is not selectable. Row insertion on the header inserts the first
body row. New columns have no explicit alignment. Delete/yank uses an editor-local
typed register: paste inserts rows/columns or replaces cells, depending on what
was copied. Yanked headers paste as body rows. Copied columns retain alignment;
paste expands dimensions if necessary to retain copied data. Cell yanks also
copy decoded text to Vim's unnamed register. Operation history excludes movement
and yanks, and retains abandoned redo branches accessible with g-/g+.

Closing or dismissing the cell float always accepts its edits, including external
window closure. Enter or Ctrl-y confirms from Normal or Insert mode; Ctrl-s and
Esc also accept. Shift-Enter or Ctrl-j inserts a newline; use Ctrl-j when the
terminal cannot distinguish Shift-Enter. Use table-level u to undo an accidental
edit, or normal buffer
undo after a direct source-cell edit. Acceptance-on-dismissal may become configurable
later. Untouched cells preserve their original Markdown spelling and add no table
undo step; dismissing an untouched direct source-cell edit does not format the
buffer. The table editor itself remains transactional: q discards the whole table.
Escaped pipes and <br> tags decode for editing; physical newlines encode as <br>
on acceptance. Unescaped pipes are escaped, even inside code spans (GFM). Normal-mode ? shows cell editor keymaps.
The Edit Cell float defaults to 64 columns wide and one line high for single-line
contents. It grows/shrinks with physical lines up to 10 lines high, staying centered
and bounded by the terminal.

Changes stay in the editor until saved. Saving is one undoable buffer edit; it
does not write the file. If the source buffer changes while the editor is open,
saving is refused: discard and reopen, or use :MDTableExport to recover staged
edits. Sorting, minification, live updates, and public configuration are deferred.

Float filetypes: markdown_table_editor, markdown_table_cell, markdown_table_help.
Their b:markdown_table_role values are editor, cell, and help, respectively.
The table title is Edit Table, or Edit Table (content) in content-navigation mode.
The wider keymaps float is titled Table Editor Keymaps (cell navigation), or
Table Editor Keymaps (content navigation), without a repeated heading in its body.
Keys align in a column using the MarkdownTableKey highlight group (default link:
Special). Its footer is ?/q/Esc: close.
Floats recenter on table size changes and terminal resizing; oversized cells
scroll to show their beginning.

No default source-buffer keys are added. Normal-mode <Plug> maps are available:
    <Plug>(markdown_table_format)
    <Plug>(markdown_table_format_all)
    <Plug>(markdown_table_edit)

Additional <Plug>(markdown_table_{action}) maps work in both source Markdown
buffers and the table preview. Supported action suffixes:
    left/right/up/down/next/previous         Navigate cells
    edit_cell                               Open cell editor
    yank_cell                               Copy decoded cell to unnamed register
    row_above/row_below                      Insert row
    column_before/column_after               Insert column
    align_left/align_center/align_right/align_none
                                            Change column alignment

Source-buffer mutations commit directly as one undoable edit. Source cell edits
only open the full preview if saving conflicts, so staged edits can be recovered.
These actions do nothing outside tables. Navigation in ragged source tables skips
omitted trailing cells; vertical movement clamps to the last physically present
cell in the target row, without modifying the buffer.

The float's typed paste register is local to its session. Direct source yank_cell
copies decoded text; native p remains ordinary Vim paste, not table-aware cell
replacement. In particular, pasting decoded multiline cells can break pipe rows.

Lua API: >lua
    require("markdown.table").format()          -- current table
    require("markdown.table").format(0, -1)     -- all tables
    require("markdown.table").format(first, last)
    require("markdown.table").edit()
    require("markdown.table").action("next")   -- same actions as Plug maps
<
The range arguments are inclusive, zero-based source rows. Intersecting tables
are formatted in full. See doc/table-design.md for design notes and open questions.

LINKS                                                         *markdown.links*

Link keymaps are set up after |markdown.nvim| is either configured with a call
to |markdown.setup()| or registered as an |nvim-treesitter| module (see
|markdown.configuration|). |<Plug>| mappings are created regardless of
configuration (see |markdown.plug_mappings|).

ADD                                                       *markdown.links.add*

Links can be added over vim motions in normal and visual mode. Links are only
added when the motion is within one inline block (i.e., not over list markers,
blank lines, etc.). In normal mode this is done with `gl{motion}` and over a
visual selection with `gl`.

FOLLOW                                                 *markdown.links.follow*

Follow inline Markdown links (`[text](destination)`) under the cursor in
normal mode with `gx`. The following destinations support in-editor
navigation:

* `#destination`: Headings in the current buffer
* `./destination`: Files and directories relative to the current buffer
* `/destination`: Files and directories relative to the working directory
* Other absolute path destinations are opened if they exist

File links can include line jumps like `#L56`, `#L56-L60` (GitHub range), or
`#L56-60` (GitLab range), e.g., `[source](./test.lua#L56)`. Only uppercase `L`
and decimal digits are supported; bare `#56` is not. Line numbers are clamped
to the file's bounds: zero jumps to the first line, and numbers past EOF jump
to the last.

Explicit link destination URIs such as `https://example.org`,
`mailto:example@example.org`, and `file:///path/document.pdf` are passed
unchanged to |vim.ui.open()| and opened with the system default handler.

Outside a supported Markdown link, `gx` delegates to the mapping that was
active before the plugin attached (likely the builtin Neovim mapping). This
preserves native URL/path handling and, where supported by the installed
Neovim version, extmark, Tree-sitter, and LSP hyperlinks.

PASTE URIS                                              *markdown.links.paste*

URIs such as `https://example.org`, `mailto:example@example.org`, and
`file:///path/document.pdf`, as well as `www.` URLs, can be pasted over a
visual selection (not a visual block selection) from the system clipboard as
markdown links.

NAVIGATION                                               *markdown.navigation*

|markdown.nvim| provides the following keymaps to navigate markdown buffers:

* Go to the current section heading     `]c`
* Go to the parent section heading      `]p`
* Go to the next section heading        `]]`
* Go to the previous section heading    `[[`

Keymaps are set up after |markdown.nvim| is either configured with
a call to to |markdown.setup()| or registered as an |nvim-treesitter| module
(see |markdown.configuration|). |<Plug>| mappings are created regardless of
configuration (see |markdown.plug_mappings|).

Runtime |ftplugin| keymaps for older Neovim versions (e.g., 0.10.0) can
overwrite |markdown.nvim| `]]` and `[[` keymaps. These can be disabled with
`vim.g.no_markdown_maps = 1`.

CONFIGURATION                                         *markdown.configuration*

|markdown.nvim| can be configured either as a standalone plugin or as an
|nvim-treesitter| module. To configure as a standalone plugin, call
`require("markdown").setup()`. To configure as an |nvim-treesitter| module,
call:
>lua
        require("nvim-treesitter.configs").setup({
            markdown = {
                enable = true,
                -- user configuration goes here
                inline_surround = { --[[ ... ]] },
                on_attach = function(bufnr) --[[ ... ]] end,
            }
        })
<
                                                      *markdown.plug_mappings*
|markdown.nvim| sets up |<Plug>| mappings regardless of configuration. Most
are used by the |markdown.config.mappings|:
>vim
        <Plug>(markdown_toggle_emphasis)
        <Plug>(markdown_toggle_emphasis_line)
        <Plug>(markdown_toggle_emphasis_visual)
        <Plug>(markdown_delete_emphasis)
        <Plug>(markdown_change_emphasis)
        <Plug>(markdown_add_link)
        <Plug>(markdown_add_link_visual)
        <Plug>(markdown_follow_link)
        <Plug>(markdown_go_current_heading)
        <Plug>(markdown_go_parent_heading)
        <Plug>(markdown_go_next_heading)
        <Plug>(markdown_go_prev_heading)
<
The following |<Plug>| mappings are not used by |markdown.nvim|'s
configuration:

`<Plug>(markdown_follow_link_default_app)`
    Like `<Plug>(markdown_follow_link)` but opens links to non-markdown files
    in the default application for the link destination. The
    |markdown.config.hooks| function `follow_link` is called before following
    the link with the option 'use_default_app' set to 'true'.


markdown.setup({opts})                                      *markdown.setup()*
    Both the standalone plugin and |nvim-treesitter| module configurations
    accept the same table argument.

    Defaults:
>lua
        require("markdown").setup({
            mappings = {
                inline_surround_toggle = "gs",
                inline_surround_toggle_line = "gss",
                inline_surround_delete = "ds",
                inline_surround_change = "cs",
                link_add = "gl",
                link_follow = "gx",
                go_curr_heading = "]c",
                go_parent_heading = "]p",
                go_next_heading = "]]",
                go_prev_heading = "[[",
            },
            inline_surround = {
                emphasis = {
                    key = "i",
                    txt = "*",
                },
                strong = {
                    key = "b",
                    txt = "**",
                },
                strikethrough = {
                    key = "s",
                    txt = "~~",
                },
                code = {
                    key = "c",
                    txt = "`",
                },
            },
            link = {
                paste = {
                    enable = true,
                },
            },
            toc = {
                omit_heading = "toc omit heading",
                omit_section = "toc omit section",
                markers = { "-" },
            },
            hooks = {
                follow_link = nil,
            },
            on_attach = nil,
        })
<

    hooks: ~

                                           *markdown.config.hooks.follow_link*
    hooks.follow_link: ~
        Overrides following recognized Markdown links with the following
        options:
            * dest: original link destination
            * use_default_app: optional boolean; whether to use the default
              application (see |markdown.plug_mappings|)
            * bufnr: source buffer number
            * kind: "heading" (starts with '#'; looked up in the source
              document), "external" (URI or URL, including www. shorthand),
              or "path" (local filesystem destination)
            * path: absolute normalized local path
            * fragment: interpreted path fragment including '#', if any
            * path_type: "file", "directory", "other", "missing", or "unknown"
            * is_markdown: path is classified as Markdown
            * line_range: parsed range fragment `{start_line=L1,end_line=L2}`
        Default: nil

        Links delegated to the native `gx` mapping do not invoke this hook.
        `path`, `path_type`, and `is_markdown` are only present for path
        links.

        Path resolution matches the fallback/default: `foo` and `/foo` are
        cwd-relative; `./foo` and `../foo` are source-buffer-relative.

        `path_type` describes filesystem inspection:
            * `"file"`: regular file; does not imply readability
            * `"directory"`: directory
            * `"other"`: another object type, e.g. FIFO, socket, or device
            * `"missing"`: ENOENT or ENOTDIR; target cannot be found at this
              path
            * `"unknown"`: another failure, e.g. permission denied; do not
              treat this as "missing".

        Example: open a buffer for a missing Markdown page:
>lua
            require("markdown").setup({
                hooks = {
                    follow_link = function(opts, fallback)
                        if opts.kind == "path" and opts.path_type == "missing"
                            and opts.is_markdown then
                            vim.cmd.edit(vim.fn.fnameescape(opts.path))
                            return
                        end
                        fallback()
                    end,
                },
            })
<
                                                   *markdown.config.on_attach*
    on_attach: ~
        Function called when |markdown.nvim| attaches to a buffer. Useful for
        creating additional buffer-only keymaps.

        Signature: fun(bufnr: integer)
        Default: nil

        Usage:
>lua
            require("markdown").setup({
                on_attach = function(bufnr)
                    local map = vim.keymap.set
                    local opts = { buffer = bufnr }
                    map({ 'n', 'i' }, '<M-l><M-o>', '<Cmd>MDListItemBelow<CR>', opts)
                    map({ 'n', 'i' }, '<M-L><M-O>', '<Cmd>MDListItemAbove<CR>', opts)
                    map('n', '<M-c>', '<Cmd>MDTaskToggle<CR>', opts)
                    map('x', '<M-c>', ':MDTaskToggle<CR>', opts)
                end,
            })
<
        `on_attach` can be used to support standard/typical inline style
        keybindings in visual mode like `<C-b>` for strong/bold and `<C-i>`
        for for emphasis/italic:
>lua
            on_attach = function(bufnr)
                local function toggle(key)
                    return "<Esc>gv<Cmd>lua require'markdown.inline'"
                        .. ".toggle_emphasis_visual('" .. key .. "')<CR>"
                end

                vim.keymap.set("x", "<C-b>", toggle("b"), { buffer = bufnr })
                vim.keymap.set("x", "<C-i>", toggle("i"), { buffer = bufnr })
            end,
